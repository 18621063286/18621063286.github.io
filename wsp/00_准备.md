# 第 0 章　准备与方法论

## 0.1 这个博客在说什么

一句话：**让一个通用的大语言模型直接读、改、写神经网络的权重，不用梯度下降。** 作者把这叫做
Weight-Space Programming（WSP）。博客用 8 个实验分别展示三种能力：

| 能力 | 实验 |
|---|---|
| 读：从权重推断网络学到了什么 | 1（游戏）、2（扩散模型）、3（语言 + 注意力头）、7（谄媚） |
| 改：定位问题并修复 | 4（小车）、8（Qwen 数学） |
| 写：从零写出能工作的网络 | 5（MinAtar 游戏）、6（围棋） |

原实验里的 LLM 是 OpenAI 的 `gpt-6-astra`（博客里叫 Astra）。在这个项目里，我们把它换成 Claude。

## 0.2 公平测试一个 LLM 的四条规矩

自己动手前，先理解这个项目为什么要搞得这么"麻烦"。这些规矩在任何 LLM 评测里都适用。

### 规矩 1：被测对象不能看到答案

你在项目里打开的 Claude Code 会话读过 `upstream/` 里的答案，所以它**只能当实验员，不能当被测对象**。
被测对象每次都是一个全新的 `claude -p` 会话：

```
claude -p --tools "" --strict-mcp-config --setting-sources "" \
  --system-prompt "Answer the user's request." --model opus --effort high
```

- `--tools ""`：没有任何工具，读不了文件，也执行不了代码。
- `--setting-sources ""`、`--strict-mcp-config`：不加载设置、memory 和 MCP。
- 工作目录放在 `/home/ken/wsp_subjects/<随机ID>/`，**在项目目录之外**。

> **小测验**：为什么工作目录一定要放在项目外面？为什么目录名不能叫 `breakout_run1`？

<details markdown="1"><summary>答案</summary>

Claude Code 会自动读取当前目录和所有上级目录里的 CLAUDE.md，而我们的 CLAUDE.md 和 PLAN.md 里写着实验信息。
另外，被测会话的上下文里能看到自己的工作目录路径，目录名叫 breakout 就等于直接把答案告诉了它。

</details>


### 规矩 2：prompt 要逐字照搬

我们比较的是"换了一个模型"，所以 prompt 必须和原实验**逐字节相同**（用 md5 校验）。
`run_subject.sh` 每次运行都会记下 prompt 的 md5。

### 规矩 3：只跑一次不算数

原实验每个配置只跑了 1 次。LLM 的输出是随机的，一次的结果可能只是运气好（或者不好）。
我们每个配置至少跑 3 次。读第 8 章时你会看到，原文中"预算越多效果越好"的结论，很大程度上就是 n=1 带来的错觉。

### 规矩 4：所有偏差都要记下来

`wsp_repro/DEVIATIONS.md` 记录了每一处和原实验不一致的地方，包括我们自己的 bug
（比如第 2 章计分脚本的子串误匹配）。**承认偏差，是结果可信的前提。**

## 0.4 读懂原始日志

先花 10 分钟浏览原作者的日志，后面每章都会用到：

```bash
cat upstream/README.md                       # 总说明：harness 怎么跑的、文件都是什么
ls upstream/exp1_which_game/runs/breakout/   # 一次运行的全部文件
less upstream/exp1_which_game/runs/breakout/answer.md   # Astra 的回答
```

每个实验目录下的 `README.md` 都有一张"博客里的数字 → 来自哪个文件"的对照表。**这是好的科研习惯**：
每个数字都能追溯到原始文件。
