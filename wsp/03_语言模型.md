# 第 3 章　从中间层认出语言、找到 copying head

> 原实验：`upstream/exp3_language/`　|　博客：Experiment 3　|　难度 ★★★　|　只需 CPU
>
> 推荐先读：Elhage et al. 2021, *A Mathematical Framework for Transformer Circuits*（transformer-circuits.pub）

## 3.1 问题

有 3 个字符级的小语言模型（4 层 × 6 个头，宽度 384，词表 28 个字符：换行、空格、a 到 z），
分别在 Python 代码、罗马字日语、英文维基上训练。**只给你中间 4 个 block 的权重**，输入嵌入（字符和位置）和输出层都被拿掉了。
**不准跑前向**（不准把网络或其中任何一层作用在任何输入上），只能做线性代数。

要回答两个问题：
1. 它是在哪种文本上训练的？
2. 24 个注意力头分别在做什么？其中哪些是 **copying（induction）head**？

> 难点在于：没有嵌入层，就**不知道 384 个维度里哪个代表哪个字符**。第 1 章"看哪里的数字大"的招数在这里完全用不上。

## 3.2 背景：把注意力头拆成两个电路

一个注意力头可以拆成两个互相独立的矩阵（每个都是 384×384，秩不超过 64）：

| 电路 | 公式 | 含义 |
|---|---|---|
| **QK 电路** | `W_QK = W_qᵀ W_k` | 决定"看哪里"：位置 i 对位置 j 的注意力分数 = `x_iᵀ W_QK x_j` |
| **OV 电路** | `W_OV = W_o W_v` | 决定"看到之后往残差流里写什么" |

**Induction head 是一个两步电路**：
1. 第一步，**previous-token head**（较浅的层）：每个位置把"前一个字符是什么"写进自己的残差流。
2. 第二步，**induction head**（较深的层）：拿"当前字符"去和每个位置上记下的"前一个字符"比较，
   找到匹配之后就复制那个位置的字符。效果是：见过 `...ab...` 之后，再看到 `a` 就会预测 `b`。

第二步的 key 读取的正是第一步写进去的信息，所以 `W_QK^{induction} · W_OV^{prev}` 应该很"强"。
这就是 **K-composition**。

### 练习 3.3　加上"符号"，再试一次（15 分钟）

关键洞察：induction head 要做的是"**当前字符 == 前一个字符**"的匹配。在 previous-token head 读取的那个字符子空间里，
`W_QK · W_OV` 应该**像一个正的单位矩阵**（同一个字符和自己匹配得最好）。所以要看的是迹（trace），不是范数：

```
score = trace(M) / ||M||_*        M = Vᵀ (W_QK · W_OV^{prev}) V
```

`V` 取 OV 矩阵的前 28 个右奇异向量（28 = 词表大小）。`score` 接近 +1，表示 M 正而且接近单位矩阵。

```bash
wsp_repro/.venv/bin/python -I tutorial/tools/e3_composition.py english B
```

对三个网络都跑一遍，把每个网络得分明显领先的头记下来。

### 练习 3.5　判断语言（开放题，20 分钟）

没有嵌入层，怎么知道训练文本是什么？两条线索可以试试：

1. **copying head 的数量**。代码里变量名、关键字会反复出现，复制的价值更高。数一数每个网络有几个 copying head。
2. **最后一层往残差流写多少个"方向"**。最后一层 MLP（`W_proj.3`）主要负责为预测下一个字符做准备。
   罗马字从来不用 q、l、v、x，只用 22 个字母，加上空格和换行一共 24 个字符；英文和 Python 会用满全部 28 个。

```bash
wsp_repro/.venv/bin/python -I - <<'EOF'
import numpy as np
for lang in ("python", "romaji", "english"):
    W = dict(np.load(f"upstream/exp3_language/networks/{lang}/blocks.npz"))
    s = np.linalg.svd(W["W_proj.3"], compute_uv=False); p = s**2 / (s**2).sum()
    print(lang, "W_proj.3 有效秩 =", round(float(np.exp(-(p * np.log(p)).sum())), 1))
EOF
```

<details markdown="1">
<summary markdown="span">参考结果与讨论</summary>


有效秩：python 34.7，romaji **31.1**，english 33.6。罗马字最低，方向和预期一致。
注意第 3 层的有效秩在 31 到 35 之间，和词表大小（28）是同一个量级，而第 1、2 层大约有 300。最后一层确实在往"字符空间"里写。

但请批判性地看：31.1 和 33.6 只差 2.5，**而每种语言只有一个网络（一个 seed）**。
如果换一个随机种子重新训练，这个差距会不会就消失了？仅凭这个数字下结论是不可靠的。
Astra 给出的概率只有 0.48 到 0.62，说明它也知道证据很弱。


</details>

## 3.6 批判性思考

1. 练习 3.2 和 3.3 说明，**方法上的一个小细节（范数还是迹）决定了成败**。博客说 Astra "独立发现了 Elhage 等人的方法"，
   其实更准确的说法是：它用对了这个方法的一个**带符号的变体**。
2. 这是 8 个实验里证据最扎实的一个：ground truth 是用前向实测的，独立于被测模型，prompt 里也没有暗示答案。
3. 但"不准跑前向"这条规则**只能靠事后审计**来保证。线性代数和"模拟前向"之间的界线在哪里？
   比如"把一个 OV 矩阵作用在另一个矩阵的奇异向量上"算不算？想一想你会怎么写审计规则。
