# 第 5 章　从零手写一个会玩游戏的网络

> 原实验：`upstream/exp5_write_from_scratch/`　|　博客：Experiment 5　|　难度 ★★　|　只需 CPU

## 5.1 问题

前面几章是"读"权重，这一章是"写"：**所有权重从 0 开始，不训练、不用数据、不跑游戏**，
只看游戏规则和源码，直接写出一个能玩 MinAtar 游戏（Breakout、Seaquest、Asterix）的策略网络。

网络和 PPO 基线用同样的结构：`600 → 32 → 32 → 6`，tanh。
- 输入：10×10 网格 × 6 个通道（player、danger、reward、projectile、trail、gauge），第 i 个输入 = `(row*10 + col)*6 + channel`
- 输出：6 个动作（no-op、left、up、right、down、fire）的 logits，**从 softmax 中采样**动作
- **计分**：1,000 局取平均分；**10% 的概率重复上一步动作（粘滞动作）**；每局最多 10,000 步

完整 prompt：`upstream/exp5_write_from_scratch/runs/breakout/message.txt`。值得通读一遍，里面附了游戏的完整源码。

## 5.2 核心原理：把程序"编译"成权重

输入是 one-hot 网格，所以第一层的一个单元能直接计算**坐标的线性函数**：

```
unit = tanh( Σ_c  w_c · [球在第 c 列] )      令 w_c = 0.3·c  →  unit = tanh(0.3 × 球所在的列)
```

再从挡板所在的列减去同样的量，就得到 `tanh(0.3 × (球列 − 挡板列))`：球在右边为正，在左边为负。
这一个隐藏单元就是一个"追球"程序。tanh 在输入较小时近似线性，输入较大时近似一个开关，两种用法都可以利用。

### 怎么写权重：edits 语言

```edits
W1[9:600:60, 0] = 0.3        # 通道 3、第 1 列的 10 个格子 -> unit 0，权重 0.3（行 c*6+ch : 600 : 60）
W1[540:600:6, 0] = [0, -0.3, -0.6, -0.9, -1.2, -1.5, -1.8, -2.1, -2.4, -2.7]   # 第 9 行（挡板）、通道 0
W2[0, 0] = 3
W3[0, 3] = 6                 # unit 为正 -> 偏向 right
W3[0, 1] = -6                # unit 为负 -> 偏向 left
```

完整语法在 prompt 末尾的 "HOW TO WRITE THE WEIGHTS"。解析器 `wsp_repro/exp5/parse_edits.py` 解析原作者的回答，得到的权重和他们发布的网络**逐元素一致**；
评测器 `minatar_eval.py` 重新评测原作者的网络，分数也和他们公布的一致（Breakout 512.5 对 517.4，都在 1 个标准误以内）。

### 练习 5.4　挑战：对抗粘滞动作

粘滞动作意味着：你**想**往左的那一步，有 10% 的概率会重复上一步的动作。
"刚好在最后一步到位"的策略会因此丢球。真正的解决办法是**提前算出球的落点，早早移过去等着**。

提示：
- 球每一步沿对角线走一格，碰到墙会反弹。给定球的位置和方向（球 + trail），落点列是一个确定的函数。
- 第一层可以用多个单元，对不同的"距离底部的行数 × 方向"组合做检测；第二层把它们合成"目标列 − 挡板列"。
- Astra 的设计（`upstream/exp5_write_from_scratch/runs/breakout/reply/answer.md`）就是：第一层计算落点，第二层移动挡板。它拿到了 517 分。

## 5.6 批判性思考

1. **PPO 基线是不是太弱了？** PPO 训练 500M 步才 25 分，而你用一个单元、几分钟就拿到 10.8 分。
   "LLM 写的网络比 PPO 训练 100M 步还强"，与其说明 LLM 有多强，不如说明这个 PPO 配置（32 宽的 MLP、这组超参数）有多弱。
   一个公平的比较需要一个调好的基线（见 `PLAN.md` 的 3.4）。
2. **被测模型拿到了游戏的完整源码。** Breakout 的球路是确定性的，有了源码，预测落点就是一个纯粹的编程问题。
   这考察的更像是"把程序编译成权重"的能力，而不是"理解一个陌生环境"的能力。
3. **方差很大。** Claude 三次分别是 60、461、79 分。如果只跑一次，结论可能是"远不如 Astra"，也可能是"和 Astra 差不多"。
4. **计分协议的随机性是设计的一部分。** 采样 + 粘滞动作专门惩罚没有容错余量的策略。练习 5.2 说明：
   一个在 argmax 条件下完美的策略，按原协议只能得 2 分。这是一个公平的设计吗？它在考察什么？
