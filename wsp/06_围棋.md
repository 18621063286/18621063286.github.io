# 第 6 章　从零写一个 150 万参数的围棋网络

> 原实验：`upstream/exp6_go_from_scratch/`　|　博客：Experiment 6　|　难度 ★★★★　|　评测需要 GPU（JAX + pgx）

## 6.1 问题

9×9 围棋，网络结构 `243 → 512 × 6 → 82`，ReLU，**1,480,274 个权重全部从 0 开始**。不准训练，不准搜索（没有 MCTS，也没有 rollout）。
- 输入：3 个平面（我方棋子、对方棋子、是否轮到白方），每个平面 81 个点
- 输出：81 个落子点 + pass，非法着法被屏蔽，按温度 1 采样

这个网络**大到放不进上下文**（150 万个数），所以 Astra 必须在沙箱里**写程序来生成权重**。
它还有 0、10、25 或 50 次"前向"预算：每次可以让网络和练习对手下最多 128 盘，或者在最多 256 个局面上查看网络的输出。

## 6.2 背景：用 ReLU 层实现围棋概念

围棋的规则可以用局部运算来表达，而 ReLU 网络天然适合做局部的逻辑运算：

| 概念 | 怎样用一层来实现 |
|---|---|
| 某个点是空的 | `ReLU(1 − 我方 − 对方)` |
| 某颗棋子有"气"（相邻有空点） | 对 4 个邻居的"空"求和，再加阈值 |
| 一整块连通的棋子是否有气 | 沿着同色棋子**一层一层传播**"有气"的信号（6 层就能传 6 步） |
| 某个着法能提子 | 对方某块棋只剩 1 口气，而这口气就是这个落点 |

Astra 在 budget 0 的运行里，用**一段 336 行的 Python 程序**生成了全部权重：早期的层标出棋子和气，中间的层沿棋块传播"危险"信号，最后一层给每个落点打分（提子、救自己的棋、避免自紧气、不填自己的眼）。

### 练习 6.3　思考题

1. **评测对手和练习对手来自同一个家族**：练习时的 "strong" 对手是 PPO seed 1，评测用的是同样配置的 seed 0 和 seed 2。

## 6.4 让 Claude 做

> ⏸️ **harness 已搭好，对手只训了一部分，被测会话还没跑**（2026-11-12 暂停）。

**确认的事实**：上游没有公开评测对手（小 PPO seed 0/2、REINFORCE seed 0/2）、练习对手（weak、strong），也没有公开对弈和训练代码，只公开了 Astra 写的 4 个网络和 3 个同规模 PPO 网络。所以对手必须自己重训。

我们写的组件（都在 `wsp_repro/exp6/`）：

| 组件 | 作用 |
|---|---|
| `gojax.py` | 用 pgx 的 `go_9x9` 规则（162 手上限、重复局面判负、数子法、贴目 7.5）批量对下两个 MLP 策略 |
| `train_opp.py` | 自对弈训练对手：小 PPO（243→32→32→82）和 REINFORCE，每轮 1,024 局，和上游一样训 20,000 轮 |
| `calibrate.py` | 用上游公开的 7 个网络当"尺子"，检查重训的对手强度是否和原版一致 |
| `pass_tool.py`、`driver6.py` | games / positions 两种 pass 和多轮循环，返回格式照上游日志；沙箱里 torch 的反向传播和优化器会直接报错 |
| `score.py` | 按上游协议计分：每个对手 2,000 局 |

**引擎校验**：同规模 PPO 对随机玩家 98.2%（上游 97.5%），Astra b0 100%（上游 99.6%）。

**怎么知道重训的对手和原版一样强？** 上游记录了 Astra 的网络和同规模 PPO 对每个对手的胜率。让它们再和我们的对手下，胜率接近就说明强度接近：

| 参考网络 | 对重训 PPO s0（第 20,000 轮） | 上游对原版 |
|---|---|---|
| Astra b0 | 54.2% | 54.5% |
| Astra b10 | 73.6% | 66.4% |
| Astra b25 | 56.8% | 69.1% |
| Astra b50 | 80.4% | 82.4% |
| 同规模 PPO s0 / s1 / s2 | 62.6 / 83.2 / 70.8% | 50.0 / 74.7 / 55.7% |

（每格 500 局。）平均偏差 +4 个点。强度随训练稳定上升：第 2,000 轮时偏差 +31 个点，第 15,000 轮 +13 个点，第 20,000 轮 +4 个点。所以规则定为一律用第 20,000 轮，不挑 checkpoint。

一个小发现：在 CPU 上训练每轮要 5 秒（20,000 轮约 28 小时），GPU 上只要 0.08 秒（约 28 分钟），pgx 在 GPU 上快了 60 倍。
